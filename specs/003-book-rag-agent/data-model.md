# Data Model: Backend Multi-Agent System for Book RAG Chatbot

**Feature**: 003-book-rag-agent
**Date**: 2025-12-31

## Overview

This document defines the data structures and relationships for the Backend Multi-Agent System for Book RAG Chatbot, focusing on the entities that flow through the multi-agent system.

## Core Entities

### UserQuery
The input from the user that initiates the agent interaction.

**Fields**:
- `query_text`: (string) The question or request from the user
- `selected_text`: (string, optional) Specific text provided by user that overrides general retrieval
- `user_context`: (object, optional) Additional context about the user's session or preferences
- `timestamp`: (datetime) When the query was submitted

**Validation**:
- `query_text` must not be empty
- `selected_text` if provided, must be meaningful length (>10 characters)

### AgentResponse
The output from the agent system to the user.

**Fields**:
- `answer`: (string) The final answer generated by the system
- `source_references`: (array) List of references to the book content used in the answer
- `confidence_score`: (float) Confidence level in the answer (0.0-1.0)
- `processing_time`: (float) Time taken to process the query in seconds
- `was_handoff`: (boolean) Whether the query was handed off from triage to query agent

**Validation**:
- `answer` must be grounded in provided or retrieved text
- `source_references` must not be empty when answer is provided
- `confidence_score` must be between 0.0 and 1.0

### RetrievedContext
The relevant passages retrieved from book content for answering the query.

**Fields**:
- `passages`: (array) List of relevant text passages from the book
- `similarity_scores`: (array) Similarity scores for each passage (0.0-1.0)
- `source_metadata`: (array) Metadata about the source of each passage (chapter, page, etc.)
- `retrieval_method`: (string) How the context was retrieved ("selected_text", "vector_search")

**Validation**:
- `passages` array must not be empty when retrieval_method is "vector_search"
- `similarity_scores` must correspond to the passages array
- All passages must be from the original book content

### AgentState
The internal state maintained by the agent system during processing.

**Fields**:
- `current_agent`: (string) The agent currently processing the request ("triage", "query")
- `query_classification`: (string) The classification result from triage ("book-related", "other")
- `context_used`: (RetrievedContext) The context used for answering
- `processing_steps`: (array) List of steps taken during processing

**Validation**:
- `current_agent` must be one of the defined agent types
- `query_classification` must be valid classification type

## Relationships

```
UserQuery --[triggers]--> AgentState
AgentState --[uses]--> RetrievedContext
RetrievedContext --[generates]--> AgentResponse
UserQuery --[receives]--> AgentResponse
```

## State Transitions

### Agent Processing Flow
1. **Initial State**: `current_agent = "triage"`
2. **Classification**: `query_classification` set to "book-related" or "other"
3. **Handoff Decision**: If "book-related", transfer to query agent
4. **Context Retrieval**: Retrieve relevant passages or use selected text
5. **Response Generation**: Generate grounded answer
6. **Response**: Return to user with source references

## Validation Rules

### From Functional Requirements
- **FR-005**: If `selected_text` is provided in UserQuery, `retrieval_method` in RetrievedContext must be "selected_text"
- **FR-006**: Every AgentResponse must have non-empty `source_references`
- **FR-007**: RetrievedContext must contain ranked passages based on relevance

### Data Integrity
- All text in AgentResponse must be grounded in RetrievedContext or UserQuery.selected_text
- No hallucinations allowed - all claims must reference source material
- Timestamps must be consistent with processing order
